# RLM RLVR Ablations Based On The Latest 9B Family

## Summary

- Use `ondemand_long_h100x8_qwen35_9b_r2_turn20_judgefix.toml` as the structural parent for the new 4B branch.
- Reorder the work into: prompt bakeoff by inference only, cost-aware reward implementation and pilot runs, 4B LoRA rank/LR sweep, full-RL-without-LoRA comparison, then distillation from large teachers.
- Treat recursion as first-class behavior. Do not add prompt text telling the model to recurse less. Cost awareness lives only in the reward.

## Key Changes

- Add prompt variants in the env wrapper, not in `rlms`: `current`, `short_v1`, `short_v2`.
- Run prompt selection before any training with the untrained 4B model under the inherited 9B-style runtime settings.
- For each prompt, run 20 eval samples with the same sampling settings and choose the winner by mean correctness first; if prompts tie on correctness, break the tie on lower total generated token cost.
- Define the 4B baseline by copying the 9B `r2_turn20_judgefix` geometry and changing only model-specific fields first:
  - model/tokenizer to `Qwen/Qwen3-4B-Thinking-2507`
  - inference TP and memory settings adjusted for 4B
  - keep the parent family's rollout geometry, sequence length, turn budget, async settings, trace export, and logging unless a smoke run shows a concrete runtime issue
- Implement cost-aware reward as a success-conditioned smooth token discount using total generated tokens across both root turns and recursive subcalls.
- Use the env's existing token accounting path as the single cost source, so the model pays for long root outputs and long recursive traces the same way.
- Make the reward formula explicit and bounded:
  - `cost_k = total_model_tokens / 1024`
  - `shaped_reward = correctness / (1 + alpha * cost_k)`
  - incorrect rollouts stay at `0`
- Reasoning for this form:
  - it preserves `correct > incorrect`
  - it does not suppress recursion categorically
  - every extra token has a consequence
  - it is smoother and less brittle than a hard cutoff or linear subtractive penalty
- Sweep `alpha` as part of the cost-awareness ablation instead of fixing it once. Use `alpha in {0.0, 0.01, 0.02, 0.05}`.
- Add env args and metrics needed to support this cleanly:
  - `prompt_variant`
  - `cost_reward_alpha`
  - `reward_correctness`
  - `reward_shaped`
  - `total_model_tokens`
- Organize RL experiments in this order:
  - prompt bakeoff on base 4B
  - cost-alpha pilot on 4B with the inherited 9B-style config and default LoRA
  - LoRA grid over ranks `{1, 4, 16, 64, 128, 256}` and the chosen LR grid on the winning prompt and winning `alpha`
  - full RL without LoRA using the same winning non-LoRA-independent settings
- For distillation, train a 4B student from successful full trajectories generated by larger teachers.
- Use three distillation arms so teacher choice is itself analyzable:
  - GPT-5.4 only
  - GLM-5 only
  - 50/50 mixed teacher dataset
- Distillation data should keep full recursive trajectories, not final answers only. Convert successful traces into prompt/completion chat examples that preserve intermediate reasoning, REPL feedback, and recursion outputs.
- Compare the best distilled 4B student directly against the best RL-trained 4B model on the same held-out eval split.

## Test Plan

- Prompt tests: every short prompt variant must preserve code-block parsing, recursion calls, and `FINAL(...)` / `FINAL_VAR(...)` termination.
- Reward tests: verify token accounting includes root turns and subcalls, and verify the shaped reward formula for multiple `alpha` values.
- Smoke gates:
  - prompt bakeoff runs complete for all prompt variants
  - one short RL smoke run passes with shaped reward enabled
  - one trace-to-SFT conversion pass produces valid prompt/completion examples
- Selection gates:
  - prompt winner chosen from 20-sample inference runs
  - `alpha` winner chosen before the rank/LR sweep
  - no-LoRA branch only starts after the LoRA branch is stable on the new reward
- Final comparison table should report, for each winning branch, at least:
  - correctness
  - shaped reward
  - total generated tokens
  - used recursion
  - number of subcalls

## Assumptions

- The new 4B configs should inherit behavior and run shape from the 9B `r2_turn20_judgefix` family, not from the older 4B configs.
- Prompt comparison is an inference-only screening stage with 20 samples per prompt before training begins.
- Cost is measured in generated tokens across all root and recursive calls, not by counting subcalls separately.
- Distillation uses both GPT-5.4 and GLM-5 as teacher sources, with full-trajectory traces and a 4B student.
